## 2026-10-14 - Global Timer causing widespread React Re-renders in large Agenda/Grid Components
**Learning:** Having a high-level `setInterval` that updates a global time state (e.g., `now`) every minute causes all children to re-render, creating a significant performance bottleneck when the child component is a large grid/list like the `AgendaView`. We found this happening to `ApptChip` components which re-rendered fully despite their visual status being unchanged.
**Action:** When a high-level component holds a timer that passes into a list/grid of items for derived state, memoize the list items using `React.memo` with a custom equality checker. Ensure the equality check compares the *derived* state (e.g., `getVisualStatus(prevAppt, prevNow) === getVisualStatus(nextAppt, nextNow)`) rather than strictly comparing the `now` integer. In addition, change inline functions passed to memoized components (like `onClick={() => onSelectAppt(a)}`) to stable function references where possible or allow the item itself to accept an item-level handler (`onSelectAppt: (item) => void`).

## 2026-10-15 - MapStruct/Manual DTO mapping triggering N+1 queries
**Learning:** Mapping methods (e.g., `mapToDTO`) that access `FetchType.LAZY` loaded `@ManyToOne` fields like `a.getPatient().getName()`, `a.getService().getName()` inside `Stream.map()` on list endpoints cause massive N+1 database queries. This happened in `AppointmentDAO` and `CalendarBlockDAO` when fetching agenda lists, which heavily degraded backend performance on busy agenda days.
**Action:** When returning a list of entities from a Spring Data JPA Repository / DAO that will be mapped to a DTO needing related entities, always add `JOIN FETCH a.relation` to the `@Query` to fetch the related entities in a single database roundtrip.
