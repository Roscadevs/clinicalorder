## 2. Detailed Component Inspections & Mocking Strategies

### 2.1 `App.jsx`
- **File**: `frontend/src/App.jsx`
- **Source Structure**:
  - Configures top-level `<BrowserRouter>`.
  - Defines public routes (`/inicio-sesion`, `/recuperacion-contrasena`).
  - Defines protected routes nested inside `<Layout>` (`/` root redirects to `/matriz-visual-agenda`).
- **Mocking Strategy**:
  - Since `App.jsx` includes `<BrowserRouter>` internally, direct rendering in tests should not be wrapped in another Router.
  - To test route navigation deterministically, window location can be set via `window.history.pushState({}, '', '/target-route')` before calling `render(<App />)`.
  - Sub-pages can be mocked via `vi.mock('./pages/InicioSesion', ...)` to isolate router mapping logic and speed up test execution.

### 2.2 `Layout.jsx`
- **File**: `frontend/src/components/Layout.jsx`
- **Source Structure**:
  - Uses `useLocation()` to detect current route.
  - `navItems`: `Agenda` (`/matriz-visual-agenda`), `Pacientes` (`/directorio-pacientes`), `Configuración` (`/configuracion-catalogo`).
  - Renders desktop sidebar and mobile bottom nav.
  - Applies active style `bg-secondary-container text-on-secondary-container font-bold scale-95` when `location.pathname.startsWith(item.path)`.
  - Renders `<Outlet />` for child views.
- **Mocking Strategy**:
  - Render wrapped in `<MemoryRouter initialEntries={['/matriz-visual-agenda']}>`.
  - Pass nested routes in `<Routes><Route path="/" element={<Layout />}><Route path="matriz-visual-agenda" element={<div>Agenda Content</div>} /></Route></Routes>`.

## 3. Comprehensive Test Scenarios for Mutation Killing (StrykerJS)

To achieve a >= 70% mutation score, unit tests must assert exact text, attributes, active conditional logic, input types, and default values so that mutations (e.g. conditional boundary shifts, string mutations, attribute deletions, element removal) trigger test failures.

### 3.1 `App.test.jsx` Scenarios
1. **Default Route Redirection**: Render `App` at `/` -> asserts window/router redirects to `/matriz-visual-agenda` and renders the Agenda title.
2. **Public Route Navigation**: Render `App` at `/inicio-sesion` -> asserts "Dermacare Elite" login text renders and Layout sidebar is NOT present.
3. **Protected Route Rendering**: Render `App` at `/directorio-pacientes` -> asserts `Layout` sidebar AND `DirectorioPacientes` title render.
4. **Other Protected Routes**: Test navigation to `/registro-paciente`, `/perfil-paciente`, `/edicion-turno`.

### 3.2 `Layout.test.jsx` Scenarios
1. **Brand & Title Rendering**: Verify "Dermacare" and "Clinical Portal" text.
2. **Nav Links Presence**: Assert links for "Agenda", "Pacientes", "Configuración", "Register Patient", "Support", "Logout".
3. **Active Route Styling (Agenda)**: Set route `/matriz-visual-agenda`, assert Agenda link has active classes (`bg-secondary-container font-bold`) while Pacientes does not.
4. **Active Route Styling (Pacientes)**: Set route `/directorio-pacientes`, assert Pacientes link has active classes (`bg-secondary-container font-bold`) while Agenda does not.
5. **Outlet Content Rendering**: Render child route element inside Outlet and assert its presence.

### 3.3 `InicioSesion.test.jsx` Scenarios
1. **Header Rendering**: Assert "Dermacare Elite" and "Clinical Portal Access" text.
2. **Email Input Attributes**: Verify `id="email"`, `name="email"`, `type="email"`, `required` attribute.
